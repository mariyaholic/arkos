## Q1: Writer tuning

The cost is index churn: each file row updates the primary key and three secondary indexes in
random order, with a 4 MB page cache (`src/db/mod.rs`) and a WAL checkpoint every 256 pages.

- During a scan only, set `cache_size` to 32 MiB (`-32768`) and `wal_autocheckpoint` to 0. At the
  end of the scan (success or failure) run `PRAGMA wal_checkpoint(TRUNCATE)` and restore the
  defaults. Peak working set must stay at or under 60 MB.
- Commit every 50,000 rows or every 2 seconds, whichever comes first, instead of every 1,000
  (`BATCH_COMMIT_ENTRIES` in `src/scan/walk.rs`). Progress and the heartbeat (Q3) still tick per
  batch of directory entries, not per commit.
- Prepare the directory INSERT with `prepare_cached`, like the file INSERT.
- Keep `synchronous = NORMAL`; in WAL it already skips the fsync per commit.
- Record a new Linux run in `docs/measurements.md` next to the old one, same fixtures and hashes.

## Q2: SM-4 lock identity check

After `try_lock` succeeds, compare the identity of the open handle with the path as it is now:
on Unix `(dev, ino)` from `fstat` against `stat(path)`; on Windows volume serial and file index from
`GetFileInformationByHandle` on the held handle against a fresh open of the path. If they differ
or the path is gone, drop the handle and retry, at most 5 times, then fail as Busy. `Drop` keeps
never unlinking the lock file. The `#[ignore]` on the SM-4 test comes off.

## Q3: S-10 heartbeat

A flock held by a live hung process cannot be taken, so the heartbeat detects and reports; it
does not break the lock.

- The scan writes a sidecar next to the lock, `<lock file>.hb`, holding one line:
  `pid=<n> started=<unix s> beat=<unix s> files=<n>`. A sidecar is used because `LockFileEx`
  makes the locked bytes unreadable to other processes on Windows.
- The beat is written from the walk's batch loop (and the MFT loop), at most every 5 seconds. No
  timer thread: a thread keeps beating while the walk is stuck, which defeats the purpose.
- The file is rewritten in place each beat; readers tolerate a partial or missing file and treat it
  as "unknown".
- When a scan cannot take the lock, the Busy error (exit 6) names the pid and, when `beat` is older
  than 120 seconds, says the scan has stalled for that long and suggests ending that process.
- `arkos status` shows each `running` snapshot as `running` or `stalled (N s)`.
- The sidecar is removed when the lock is released normally; a stale one is ignored when its lock is
  free.

## Q4: Experimental MFT

- `--mode auto` never picks MFT. `--mode mft` exits 2 unless `--experimental` is also passed, with a
  hint naming the flag. Update the mode resolution test table.
- With the flag, stderr prints one line saying the MFT reader is experimental and untested.
- The snapshot `mode` stays `mft` (the CHECK constraint allows only `mft` and `walk`).
- The scan log records USN ranges, record and directory counts, orphan parent FRNs, phase timings
  and any Win32 error code.
- `scripts/compare-mft.ps1 -Root X:\` runs a walk scan and an experimental MFT scan of the same root,
  then `arkos diff` between them, and prints file and directory counts, total bytes, and the top
  paths present on one side only. The user guide lists the expected gaps: hardlinks, alternate data
  streams, NTFS metafiles, and folders the walk was denied.
- The user guide says to test on a small USB stick or VHD first.
- `release.yml`: a tag containing `-` (for example `v0.2.0-exp.1`) publishes a prerelease that is
  not marked latest.

## Q5: Advisory additions accepted

- **Cloud placeholders.** Files with `FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS`,
  `FILE_ATTRIBUTE_RECALL_ON_OPEN` or `FILE_ATTRIBUTE_OFFLINE` are counted as `placeholders` in the
  scan stats, printed in `scan` text and JSON, and logged. Sizes stay logical (H1 decision); no
  schema change.
- **Long paths.** Confirm the walk reaches paths longer than 260 characters on Windows (Rust's
  `std::fs` adds the verbatim prefix itself) and that any raw `CreateFileW` call in the MFT path does
  the same. A Windows-only test builds a path over 300 characters and scans it.
